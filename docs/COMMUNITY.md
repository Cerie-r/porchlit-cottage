# 自建小屋与共同社区

状态：已确认的产品方向；社区服务尚未实现。本文不是现有联网能力或正式许可证。

## 自由与边界
允许住户自由装修、换色、换装、设计房型。代码按 AGPL-3.0（或更新的版本）发布，见 LICENSE：谁都可以用、改、自建，也可以拿去开站；改过的版本发给别人，或者开站给别人用，要把改过的源码按同样的许可公开。在官方社区里，不得冒充官方或其他住户、作弊、破坏他人数据或向社区传播恶意代码。不能以“审美离谱”为由限制正常创作。
代码授权与社区准入分别管理。第三方素材不自动获得本项目的再授权，各自的来历见 CREDITS.md。

## 三类数据
1. 私人小屋：家具布局、装饰、穿搭与私人纸条，由住户控制。搬家箱只处理本机小屋存档，不赋予社区身份或物品所有权。
2. 公开参观快照：住户主动发布的布局与经审核的素材引用。默认排除纸条正文、聊天、密钥、账户凭据及其他私人记录。社区提供独立只读展示，不嵌入自建站任意脚本。
3. 社区权威数据：账号、门牌、认证收藏、抽奖和赠礼记录，由社区服务器保存与验证。本地修改背包不能改变这些记录。

## 本地与自建接入
官方网页、本地客户端及自建站均可作为接入端；住户身份不绑定部署域名。第一版自建前端只供部署者本人使用，使用自己的用户名和密码登录官方 API，以可撤销的 Bearer 会话认证；部署配置只放公开服务地址。不要在别人部署的前端上输入密码。AI 独立注册并使用固定 MCP 钥匙，与人双向确认同住；第一版不做 OAuth。详细规则以服务器代码（`server/accounts.mjs`、`server/mcp.mjs`）为准，不能用搬家箱里的字符串冒充账号。
社区入口地址为部署配置，不能写死在房间或角色逻辑中。未配置或服务不可用时保留离线装修能力，不显示虚假的联网成功状态。
本地电脑不需要公开端口即可发布参观快照；主人离线后可继续展示最后一次主动公开的版本。撤回公开与删除素材需要同步处理。

## 物品来源
自制家具使用独立命名空间（例如 custom:<creator>:<item>），允许参与装修展示，清楚标注自制；不能冒用官方限定物品编号或伪造收藏认证。
认证物品使用服务端唯一实例 ID；赠礼、抽奖及未来交易必须在服务端做身份、所有权、幂等与并发校验。客户端提供操作请求，不提供最终余额和开奖结果。

## 后续实施顺序
1. 数据库与账号、跨设备私有存档，明确恢复与冲突规则。
2. 门牌与主动公开的只读参观快照、素材上传限制和举报机制。
3. 本地/自建端授权接入与协议版本兼容。
4. 社区抽奖和赠礼账本；再开放扭蛋机、盲盒机。

当前发布只完成离线小屋及存档搬迁；以上服务不得直接依赖浏览器 localStorage 作为权威数据。
