# Porchlit · Heroku 迁移

## 当前阶段
此版本迁移完整的浏览器小屋：React/R3F 场景、衣橱、角色模型、家具互动和本机存档。
数据库已经接上连接和第一批表（账户、会话、恢复码、小屋、存档），人的账号接口和存档接口也有了（注册、登录、退出、改密、恢复码找回、读写小屋存档，路由在 `server/api.mjs`）。小屋页面上的门廊灯接上了这些接口：点灯（登录或注册）以后，家在这台设备上照旧存一份，云上也存一份，换设备推门是同一个家（见下面的「门廊灯」）。AI 的门（MCP）在 `/mcp`，见下面的「AI 的门」。
服务只读取构建后的 dist；不把住户数据写进 Heroku 临时磁盘。

## 构建与启动
- Node 24.x（密码用 Node 自带的 Argon2，要 24.7 以上）；`npm ci` 安装锁定依赖。
- `npm run build` 生成房屋和服装资源并构建全部入口。
- `npm start` 启动生产 HTTP 服务，监听 Heroku 提供的 PORT 和 0.0.0.0。
- Procfile 声明 web 进程和 release 阶段的迁移；heroku-postbuild 在部署阶段构建，不在启动时重复构建。
- `/health` 返回状态和数据库状态；`/` 小屋、`/body/` 衣橱、`/transfer/` 搬家箱。
- 在 Heroku 手动部署 main，确认成功后开启一个 web dyno。数据库附加服务可以晚点加，加了以后下一次部署会自动建表。
- 第一次验证手动部署，检查模型、换装、保存、刷新和搬家，再决定是否打开自动部署。

## 数据库
- 加了 Heroku Postgres（Essential-0）以后，Heroku 自己会给 `DATABASE_URL`。没有它，小屋照常只发页面，`/health` 里的 `database` 是 `off`。
- 迁移：`server/migrations/` 里按编号排的 SQL 文件（`001` 账号和存档，`002` 存档的 saveId 和旧版本）。每次部署，Heroku 先在 release 阶段跑 `node server/migrate.mjs`，没跑过的文件按顺序放在一个事务里执行，要么全进，要么一条都不进；失败了这次发布就不上线，旧版本照常跑。所有跑迁移的进程抢同一把咨询锁（advisory lock），两边同时跑也只会跑一遍。
- 跑过的迁移文件不能再改：每个文件的校验和都记在 `schema_migrations` 里，改过的会被拒绝。新的改动写成下一个编号的文件。代码回滚以后，库里多出来的较新编号不去动它。
- `/health` 里的 `database`：`off` 没配数据库；`ok` 正常；`behind` 还有迁移没跑；`changed` 跑过的迁移被改过；`down` 连不上（最多等两秒）。
- 连接数：每个进程最多 `PG_POOL_MAX` 条（默认 5，最多 18）。Essential-0 一共只给 20 条：进程数 × `PG_POOL_MAX`，加上 release 阶段的 1 条，再给维护留 1 条，合计要在 20 以内。
- SSL：远程数据库默认加密、不验证证书（Heroku Postgres 的证书不在默认的信任名单里）；本机数据库不加密。可以用 `DATABASE_SSL`（`disable` / `no-verify` / `verify`）或网址里的 `sslmode` 改。
- 本地测试：`TEST_DATABASE_URL=postgres://用户@127.0.0.1:5432/postgres npm test`。每条测试自己建一个空库，用完就删，所以这个用户要有建库的权限。不设的话，数据库那几条测试会跳过。

## 门廊灯（登录和云上的家）
- 顶栏「去散步」左边的小灯，和外景门两边的两盏灯，点了都打开门廊灯的卡片。没登录时灯是暗的，登录以后亮着。
- 家还是存在浏览器里，键和搬家箱一样（`src/home-transfer.js`）。门廊灯自己另用两个键：会话、上次同步到哪一版；这两个不跟着家走，搬家箱也不带。
- 打开页面时，如果这台设备登录着，先问一次云上的存档（最多等五秒），只有云上变了就先换上再画房子；要存上去、或者要问人的，等房子画出来再做（`src/porch-sync.js`）。
- 规则（`decide`）：只有云上变了就换上云上的；只有这里变了就存上去；两边都变了、这台设备第一次见这个家、或者云上的比这台设备上次见的还旧（数据库恢复过），都停下来问人留哪一份，不替人决定。
- 不管留哪份，被换下来的都先存进云上的旧版本（`home_history`，每家最近四十份，合计不超过 12 MB；有意留下的比平常十分钟留一份的后删）：选「用云上的」时，设备先把自己这份交上去，交不上就先不换（太大、有怪字符交不上的，可以先下载成文件，说一声存好了再换）；选「用这台设备上的」时，服务器把它原来那份放进去。卡片里「云上的旧版本」能下载、能换回。
- 开着的页面每三秒看一眼这台设备有没有改动，停手四秒后存上云（一直在改的话最多等三十秒）；每分钟问一次云上的版本号（只要号码，不拉整份），切回这个标签页时也问。别的设备存过新的，就在灯上冒个小点，点了换上；不会自己刷新页面。
- 存的时候先在同步记录里记下「正在存哪一版」：回答丢了（网断在半路）、下次见面时认得出那是自己存上去的，不会当成别的设备。
- 连不上云：家照常存在这台设备上，十秒、二十秒……最多五分钟再试一次。超过 6 MB、或者里面有数据库存不进去的字符，就停下来说明，等下一次改动再试。会话过期了，灯熄掉，提示再点一次灯。
- 同一个浏览器开着两个小屋标签：一个改了家，另一个就整页蒙上，只剩「刷新这一页」，这一页对家的写入也一律不算，免得把旧的写回去；切回那一页时自己刷新（备用钥匙还在屏幕上时除外）。另一个标签页换了账号也一样。衣橱是开在小屋里面的，它的保存不算另一个标签页。
- 预览域名（Cloudflare Pages 之类）没有 `/api`，在那里点灯只会提示连不上，不会碰到正式的存档。
- 数据库从备份恢复以后：在 Heroku 的 Config Vars 里给 `SAVE_EPOCH` 换一个新值（比如恢复那天的日期），再重启。设备会把云上的家当成没见过的，每台都先问一次留哪份，不会悄悄把只在某台设备上的改动换掉。
- 上线后第一次点灯：在家在的那台设备上先点（注册），家就存上去了；别的设备再点灯，会问一次留哪个，选云上的。

## AI 的门（MCP）
- 地址：`https://porchlit.party/mcp`。AI 的钥匙地址是 `https://porchlit.party/mcp?token=pck_…`，在 claude.ai 的连接器里加。怎么让 AI 住进来见 README 的「让 AI 住进来」。
- **签名密钥**：Config Vars 里加 `PORCHLIT_KEY_SECRET`，一串至少 20 个字的随机字（比如密码管理器生成的强密码）。**定了就不能换**：换了所有 AI 的钥匙一起作废。所以服务器在 release 阶段和每次启动都拿它去验库里的金丝雀，对不上就不上线、不启动（日志里写着），把原来那串放回去就好。没设这个变量时，网站照常，AI 的门只说还没配好钥匙。
- 地址的写法：默认照请求的域名写；要固定成一个，设 `PUBLIC_URL`（比如 `https://porchlit.party`）。
- **日志里遮住钥匙**：钥匙放进连接器的「请求标头」（`X-Porchlit-Key`）就不在网址里。放在网址的 `?token=` 里时，Heroku 的路由日志默认会记下整个网址。用 Heroku CLI 跑一次 `heroku features:enable http-router-no-log-query -a <app>`，查询串就记成 `REDACTED`。服务器自己从不记网址。
- `mcp.porchlit.party`：以后想用这个短一点的地址，在 Heroku 加这个域名、在 Cloudflare 加一条指过去的 CNAME；这个域名的根就是 AI 的门，不用改代码。

## 搬存档
1. 用原来玩小屋的同一浏览器、同一网址打开 `/transfer/`，导出 JSON。
2. 每个设备可能有不同的本地存档；选择需要保留的版本分别备份，不自动合并。
3. 新网址打开 `/transfer/`，选择 JSON，检查提示后导入。
4. 导入前自动下载新网址现有数据备份；导入替换该网址的全部受支持小屋存档，其他存储键保留。
5. 家具位置、旋转、颜色、作品、纸条、查找进度、材质、灯光、时区、男女穿搭、操控角色一起带走。
6. 关闭其他小屋标签再导入，避免旧页面把过时状态写回来。回家后刷新核对。
7. 临时 Heroku 域名换成 porchlit.party 时也要导入一次；浏览器存储按域名隔离。

## 数据与默认模板
- `src/house-catalog.js`：基础家具目录、房间和默认色板；住户实际选择保存在独立状态中。
- `src/decor-state.js` / `surface-state.js`：材质部位、颜色与布料目录；样本册支持自选漆面、台面、描边和线条颜色。
- `body/wardrobe-state.js`：两位住户独立的穿搭和 playerKind。`body/avatar-model.js` 消费这些数据。
- `public/wardrobe/` 和 `body/wardrobe-pictures.json`：衣橱里套装和头饰卡片上的照片（照着做好的衣服拍的），衣橱一打开就有，不用等模型。改了衣服或头饰要重拍：`npm run build`，再 `PLAYWRIGHT=…/node_modules/playwright npm run wardrobe:pictures`；忘了重拍，`tests/wardrobe-pictures.test.mjs` 会提醒。头发、头像这些跟着她的样子变的，照片留在浏览器里，下次打开先用。
- `src/home-transfer.js`：可移植存档版本、允许导出的存储键和导入检查。
- 现有模型是可复用的默认家具；还未改为任意家具模型注册/下载系统。扩展房型和任意新增家具仍需开发。
- 模型造型不在迁移时替换。
